## 5. investigate: does better-auth 1.7.3 actually need the account-identity schema change?

This group was originally scoped as "feat: model better-auth account identity in the schema" (add `Account.issuer` + regenerate the `init` migration, per the exploration phase). Before hand-editing `auth.prisma` (task 5.1 as originally written), verification found the premise no longer held — see below. No `auth.prisma` or migration file was touched. Full write-up in `proposal.md` ("Investigated and not carried forward") and `design.md` (decisions D1/D2/D4, marked withdrawn).

- [x] 5.1 `packages/database`: attempted `npx @better-auth/cli generate` against the `apps/auth` configuration; the CLI cannot introspect a `betterAuth()` instance built inside a NestJS DI factory (`app.module.ts`) rather than a conventional exported `auth.ts` — confirmed by running it directly, which reported "No configuration file found" / "Couldn't read your auth config". Fell back to reading the exact installed version's own schema-definition source instead of the CLI output
- [x] 5.2 `packages/database`: compared `@better-auth/core@1.7.2`'s and the installed `@better-auth/core@1.7.3`'s `src/db/get-tables.ts` directly (both ship TypeScript source in the published package) — 1.7.2 declares `issuer` as a required `account` field with a unique `[issuer, accountId]` index; 1.7.3 has neither. Cross-checked 1.7.3's own `schema-diff.ts`, whose hint text for an unexpected-required `issuer` column reads "If this column came from Better Auth 1.7.0 through 1.7.2, follow the upgrade guide before **removing** it" — the tool exists to undo the 1.7.0–1.7.2 change, not apply it
- [x] 5.3 confirmed via `gh release view v1.7.3 --repo better-auth/better-auth`: official release notes state "We restored the 1.6 account core schema to avoid requiring a disruptive backfill for existing users... If you applied the 1.7 issuer schema, follow the upgrade guide for the required cleanup. No backfill is needed," with the fixing PR titled "Restored compatibility with 1.6 account schemas by identifying accounts with `(providerId, accountId)` instead of issuer"
- [x] 5.4 empirical verification: wrote a throwaway script (deleted after use, never committed) that constructed a real `betterAuth()` instance with the `PrismaPg` adapter against the actual local Postgres test database and called `auth.api.signUpEmail()` directly (not a test-factory bypass) — succeeded, producing an `account` row with no `issuer` field, matching the source-code finding; cleaned up the created test row and disconnected
- [x] 5.5 updated `proposal.md` (added "Investigated and not carried forward," removed the `better-auth-account-identity` capability and its Impact/Risk references), `design.md` (D1/D2/D4 marked withdrawn and rewritten to record what was considered without presenting it as applied), deleted `specs/better-auth-account-identity/spec.md`, and corrected the `CORNER_CASES.md` migration-regeneration entry (which had cited this exact change as its example) to describe an unexercised policy rather than something already done
- [ ] 5.6 `apps/auth`: run the e2e suite (`pnpm --filter auth test:e2e`) as a final confirmation that sign-up and sign-in succeed end-to-end against the unchanged schema — blocked by the same local Docker Mongo volume permission error noted in 4.4; carried forward to task 7.1/7.3
